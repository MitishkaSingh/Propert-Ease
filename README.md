# Propert-Ease
Group Project developed using Kotlin and Visual Studio. Developed to manage project plans and maintenance request.

## 1. Project Overview

**Propert-Ease** is an Integrated Construction and Maintenance Management System developed for **Dr Majoko Projects**. The application is designed to streamline construction project coordination, property maintenance management and communication between clients, contractors, administrators and project managers.

The system provides a centralised platform where users can manage maintenance requests, monitor project progress, communicate with relevant stakeholders and access information according to their assigned roles.

The primary objective of Propert-Ease is to improve operational efficiency, simplify maintenance processes and enhance transparency throughout construction and property management activities.

## 2. Project Objectives

The main objectives of Propert-Ease are to:

- Centralise construction and property maintenance activities.
- Simplify the submission and management of maintenance requests.
- Improve communication between clients, contractors and project managers.
- Provide role-based access to application functionality.
- Allow users to monitor project and maintenance progress.
- Improve the organisation and accessibility of project information.
- Enhance security and accountability through controlled access.

## 3. Key Features

### 3.1 User Authentication and Access Control
- User authentication and account management.
- Role-based access control (RBAC).
- Different dashboards and functionality depending on user roles.
- Restricted access to authorised system features.
- Secure handling of user information.

### 3.2 Maintenance Request Management
- Clients can submit property maintenance requests.
- Maintenance requests are stored and managed centrally.
- Requests can be monitored through their respective statuses.
- Relevant users can access and manage maintenance information.
- Maintenance data is organised to simplify tracking and administration.

### 3.3 Project Management
- Centralised management of construction-related information.
- Project monitoring and progress tracking.
- Access to relevant project information according to user permissions.
- Improved coordination between project managers and contractors.

### 3.4 Dashboards
The application provides role-specific dashboards to give users access to relevant information and functionality.

Dashboards are designed to improve navigation and provide a central point for managing activities within the system.

### 3.5 Messaging and Communication
- Provides communication functionality between relevant users.
- Supports collaboration between project stakeholders.
- Helps streamline communication regarding maintenance and project activities.

## 4. User Roles

Propert-Ease implements four primary user roles:

| User Role | Responsibilities |
|---|---|
| Client | Submits maintenance requests and monitors relevant request information. |
| Contractor | Accesses relevant maintenance and construction activities. |
| Project Manager | Oversees project activities, maintenance coordination and progress. |
| Administrator | Manages system-level activities, users and administrative functionality. |

Each role has access to functionality appropriate to its responsibilities.

## 6. System Architecture

Propert-Ease follows a web-based application structure consisting of the following components:

**Presentation Layer**
- User interface and navigation.
- Role-specific dashboards.
- Forms for submitting and managing information.
- Messaging and other interactive features.

**Application Logic Layer**
- Handles application functionality and business logic.
- Processes maintenance-related operations.
- Controls user permissions and access.
- Manages information displayed across the application.

**Data and Backend Layer**
- Firebase integration for backend and data-related functionality.
- Maintenance request data management.
- Application data storage and retrieval.

## 7. Security Implementation

Security was an important consideration during development.

The application incorporates security-related considerations such as:

- Role-Based Access Control (RBAC).
- Authentication and authorised access.
- Secure communication through HTTPS.
- Firebase-related security considerations.
- Consideration of South Africa's Protection of Personal Information Act (POPIA).

These measures aim to protect user information and ensure that application functionality is accessible only to authorised users.
